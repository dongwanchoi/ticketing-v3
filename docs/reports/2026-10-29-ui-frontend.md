## Implementation and decisions
- Buyer presentation split into discovery, performance detail/session picker, seat workspace/checkout, active-hold restoration and ticket history. `use-buyer.ts` extracts the existing hook/state/transactions while retaining request generation, idempotency keys, acknowledged mutation state and owner-only restoration. A local presentation flag hides old checkout panels when returning/searching; server holds are preserved and explicitly restorable.
- Shared UI includes semantic labelled Field/Panel, Poster, Status, Loading/Empty/Notice and Dialog. CSS tokens define primary/surface/text/border/status colors, space/radius/shadow/content width and responsive breakpoints. Design mirrors the documented source rather than adding arbitrary category filters, invented sale badges or external assets.
- Header keeps MOMENT purple M identity with explicit Ticketing V3 sublabel. Authentication moves from the public catalogue to a focused header dialog. Existing session/CSRF/API logic is unchanged. Dialog restores opener focus, traps Tab, supports Escape, makes background siblings inert and locks background scroll. No new dependency. Alternative native dialog would simplify behavior but needs broader test-environment integration; custom minimal dialog is directly regression tested.
- Public consumer cards remain full clickable surfaces with existing accessible `title 상세 보기` labels. Detail separates poster/intro from sticky session cards on desktop; narrow widths stack naturally. Search remains usable as compact navigation in detail, with real server querying and no mock fallback.
- SeatMap only groups existing server labels into rows (A-1/A1 etc); unknown labels retain original fallback order. No seat IDs, prices, inventory, holes or grades are invented. Original server seat IDs flow unchanged to the hold API. Arrow/Home/End navigation skips unavailable seats; explicit row labels, state legend, pressed state, 44px mobile targets, stage direction and horizontally scrollable layout improve use without distorting large venue geometry. API lacks buyer seat geometry, so this is labelled row grouping, not a claim of full floor-plan coordinates.
- Checkout has a separate summary, authoritative server amount, progress/urgency countdown, distinct confirmed/failed output and unchanged disabled/retry restrictions. All own active holds remain visible; selection revalidates server expiry/ownership. No client storage of sensitive state.
- Seller workspace has actual-data counts and explicit tasks `공연장 관리` → `공연 등록 관리` → `회차·판매 관리`, auto-advancing after actual registration success. One selected performance's session/sale forms are shown; record changes remount forms to avoid carrying values to another record. No fake review-request workflow: registration already creates PENDING. Missing sale-period read data is explicitly explained instead of invented.
- Admin list/detail uses actual ManagedPerformance fields only. Approve/reject opens a cancellable confirmation dialog; the existing API is called only on `승인 확정`/`반려 확정`. No applicant, submission date, rejection reason or new review state is fabricated. Self-approval remains server-enforced.

The single Next App Router root route is retained with explicit local views/breadcrumbs so this redesign does not silently replace session/hold safety behavior. Tradeoff: views are not individually deep-linkable routes; a future routing change should retain the same restoration and regression coverage. No new npm dependency or lockfile change. Prettier3.8.1 was invoked once as transient formatting tooling, not added to product dependencies.
